# 🌱 پلتفرم رشد نخبه

سامانه جامع آموزشی، پرورشی و مدیریتی کانون‌های نخبه‌پروری (پایه‌های چهارم تا نهم) — کاملاً فارسی، راست‌به‌چپ، با تاریخ شمسی و اعداد فارسی، واکنش‌گرا برای موبایل و دسکتاپ، و چندکانونی (هر کانون نام و لوگوی خودش را در سربرگ دارد).

پنل مستقل **مشاور** شامل داشبورد، پرونده دانش‌آموزان، مطالعه و آزمون، برنامه شخصی هفتگی، جلسات و گزارش‌ها است. حساب مشاور را از «مدیریت مشاوران» در پنل مدیر کانون بسازید و در صفحه ورود، نقش «مشاور» را انتخاب کنید. [راهنمای پنل مشاور](docs/counselor.md)

## اجرا

پیش‌نیاز: فقط **Node.js نسخه ۲۲.۱۳ یا بالاتر** (پیشنهادی: ۲۴). هیچ بسته npm لازم نیست؛ پایگاه داده SQLite داخلی Node است.

```bash
npm run seed
```

```bash
npm start
```

سپس `http://localhost:3000` را باز کنید. (پورت با متغیر `PORT` قابل تغییر است.)

> `npm run seed` پایگاه داده را پاک و با داده‌های نمونه از نو می‌سازد. تاریخ‌های نمونه نسبت به «امروز» ساخته می‌شوند؛ هر وقت خواستید دموی تازه داشته باشید دوباره اجرا کنید.

### حساب‌های نمایشی (رمز همه: `123456`)

| نقش | ورود با | توضیح |
|---|---|---|
| دانش‌آموز | `student` یا کد ملی `0012345679` | آرین رضایی، پایه هفتم — امروز تولدش است 🎂 |
| دانش‌آموز (پنل قفل) | `student9` | کیان رضایی، پایه نهم — مهلت حق عضویت گذشته |
| معلم | `teacher` | مریم احمدی، ریاضی هفتم تا نهم |
| مدیر کانون | `manager` | کانون شهید کاظم آشتیانی |
| والدین | موبایل `09120000000` | پدر سه فرزند (آرین، سارا، کیان) |
| مدیر سامانه | `admin` (لینک «ورود پشتیبانی» در صفحه ورود) | دسترسی به همه کانون‌ها و همه کاربران |
| مدیر کانون دوم | `manager2` | کانون نخبگان فردا (نمایش چندکانونی) |

بقیه ۴۸۰ دانش‌آموز نمونه با کد ملی خودشان و رمز `123456` وارد می‌شوند. دانش‌آموزی که مدیر ثبت‌نام می‌کند با کد ملی و رمز اولیه «کد ملی» وارد می‌شود؛ والد او با موبایل و رمز اولیه «۶ رقم آخر موبایل».

## راه‌اندازی روی سرور واقعی (حدود ۵۰۰ دانش‌آموز)

سرور مجازی معمولی کافی است: ۲ هسته، ۲ گیگابایت حافظه، Ubuntu و Node.js ۲۲.۱۳ به بالا. (در تست بار، ۱۰۰۰ دانش‌آموز هم‌زمان فقط ۱۵۰ مگابایت حافظه گرفت.)

1. پروژه را در `/srv/roshd` بگذارید. **`npm run seed` را روی سرور واقعی اجرا نکنید**؛ (و اگر اجرا شود، روی پایگاه داده‌ی دارای کاربر بدون `--force` متوقف می‌شود).
2. ساخت کانون و حساب‌های مدیر (رمز تصادفی فقط یک‌بار چاپ می‌شود):
   ```bash
   npm run init -- --center-name "کانون نخبه‌پروری شهید کاظم آشتیانی" --slug ashtiani --manager-name "نام مدیر"
   ```
3. معلم‌ها و کلاس‌ها را از پنل مدیر کانون بسازید، سپس دانش‌آموزان را گروهی ثبت کنید. یا از دکمه «ثبت‌نام گروهی (CSV)» در پنل مدیر، یا:
   ```bash
   node scripts/import-students.mjs --template > students.csv      # فایل نمونه
   npm run import -- students.csv --center ashtiani --dry-run      # فقط بررسی و گزارش خطای هر سطر
   npm run import -- students.csv --center ashtiani                # ثبت
   ```
   ۵۰۰ دانش‌آموز با والدینشان در حدود ۱۰ ثانیه ثبت می‌شوند. رمز اولیه دانش‌آموز کد ملی و رمز اولیه والد ۶ رقم آخر موبایل است؛ از آن‌ها بخواهید پس از ورود رمز را عوض کنند.
4. اجرا به‌صورت سرویس و پشت Nginx با HTTPS: فایل‌های آماده در پوشه [`deploy/`](deploy): `roshd.service` (systemd)، `nginx.conf`.
5. پشتیبان‌گیری: سرور خودش **هر شب ساعت ۳ (وقت تهران)** پشتیبان می‌گیرد و ۱۴ نسخه آخر را نگه می‌دارد (`data/backups/`). این نسخه‌ها روی همان دیسک‌اند؛ با `deploy/rsync-backup.sh` به سرور دیگر کپی کنید و پوشه `uploads/` را هم ببرید. بازیابی: از پنل مدیر سامانه، یا با سرور خاموش `npm run restore -- data/backups/<فایل>.db`.
6. پایش: `GET /api/health` (برای مانیتورینگ) و برای مدیر سامانه `GET /api/admin/metrics` (تأخیر حلقه رویداد، حافظه، تعداد درخواست و خطا). درخواست‌های کندتر از ۸۰۰ میلی‌ثانیه و خطاهای ۵۰۰ در خروجی سرویس (`journalctl -u roshd`) چاپ می‌شوند.

### متغیرهای محیطی

| متغیر | پیش‌فرض | کاربرد |
|---|---|---|
| `PORT`، `ROSHD_HOST` | ۳۰۰۰، `0.0.0.0` | پشت Nginx حتماً `ROSHD_HOST=127.0.0.1` |
| `ROSHD_TRUST_PROXY` | خاموش | پشت Nginx روی `1` بگذارید تا آی‌پی واقعی از `X-Forwarded-For` خوانده شود |
| `ROSHD_COOKIE_SECURE` | خودکار | با `1` کوکی فقط روی HTTPS ارسال می‌شود |
| `ROSHD_SECRET` | فایل `data/secret.key` | کلید امضای جلسه‌ها |
| `ROSHD_DATA_DIR`، `ROSHD_UPLOAD_DIR` | `data/`، `uploads/` | مسیر داده‌ها |
| `ROSHD_BACKUP_HOUR`، `ROSHD_BACKUP_KEEP` | ۳، ۱۴ | ساعت و تعداد پشتیبان خودکار |
| `ROSHD_USER_BURST`، `ROSHD_USER_RPS` | ۶۰، ۸ | سقف نرخ درخواست هر کاربر (نه هر آی‌پی؛ چون صدها دانش‌آموز ممکن است پشت یک آی‌پی مدرسه باشند) |
| `ROSHD_SLOW_MS`، `ROSHD_LOG=1` | ۸۰۰، خاموش | آستانه ثبت درخواست کند / ثبت همه درخواست‌های API |
| `ROSHD_ALLOWED_ORIGINS` | خالی | مبدأهای اضافه مجاز برای درخواست‌های نوشتنی (دامنه دیگر) |
| `ROSHD_SMS_PROVIDER` | `simulated` | `kavenegar` یا `webhook` برای پیامک غیبت واقعی؛ تنظیمات در `server/sms.js` |

### نتیجه تست بار (`npm run loadtest`)
روی یک رایانه ۱۶ هسته‌ای، یک پردازش Node، با ورود دسته‌جمعی و گشت‌وگذار واقعی هر دانش‌آموز (داشبورد، تکالیف، آزمون، مطالعه، پیام‌رسان…):

| سناریو | درخواست در ثانیه | خطا | p95 بدترین API |
|---|---|---|---|
| ۵۰۰ نفر، ورود در ۱۰ ثانیه، فایل‌ها بار اول | ۳۰۸ | ۰ | ۸۳۸ میلی‌ثانیه (ورود) |
| ۵۰۰ نفر، فایل‌ها در کش مرورگر | ۴۰۳ | ۰ | ۳۶۱ میلی‌ثانیه |
| ۱۰۰۰ نفر | ۶۶۰ | ۰ | ۳۵۰ میلی‌ثانیه |
| ۵۰۰ نفر هم‌زمان آزمون آنلاین را شروع و ارسال می‌کنند | ۹۱۹ | ۰ (۶ ارسال تکراری حساب‌های مشترک رد شد) | — |

بدترین حالت، ورود هر ۵۰۰ نفر در ۲ تا ۳ ثانیه است (هش امن رمز حدود ۲۶ میلی‌ثانیه پردازنده می‌برد): ورود تا چند ثانیه کند می‌شود ولی خطا نمی‌دهد. پیش از بهینه‌سازی همین تست خطای اتصال و تأخیر ۱۵ تا ۳۰ ثانیه‌ای داشت.

### آزمون‌های خودکار
`node scripts/test-classes.mjs` مدیریت کلاس‌ها را با مسیرهای واقعی و پایگاه داده‌ی موقت می‌آزماید (۲۰ بررسی: دسترسی، جداسازی کانون‌ها، تغییر نام، حذف/ادغام، راه‌اندازی پسر/دختر، ثبت‌نام گروهی پس از تغییر نام).

`npm run smoke` سرور موقت با داده نمونه بالا می‌آورد و ۶۳ بررسی انجام می‌دهد: دسترسی هر نقش، قفل پنل بدهکار، جریان آزمون و پرداخت رسید و خرید، و باطل شدن نشست پس از تغییر رمز.

## امکانات

**مشترک:** ورود با انتخاب نقش • اطلاعیه‌های دیده‌نشده به‌صورت تمام‌صفحه و پشت‌سرهم با دکمه «دیدم» • تبریک تولد تمام‌صفحه با کاغذرنگی • قفل پنل دانش‌آموز پس از مهلت حق عضویت (فقط پرداخت و اطلاعیه باز می‌ماند) • پیام‌رسان داخلی امن بدون نمایش شماره تلفن • تغییر رمز.

**دانش‌آموز:** داشبورد با امتیاز، سطح (۸ سطح از «جوانه» تا «نخبه»)، رتبه در پایه، تکالیف نزدیک به مهلت با شمارش معکوس، کلاس امروز، سکوی برترین‌های مطالعه امروز/هفته، کارت مسیر یادگیری، بازی و داستان • تکالیف با ارسال فایل و یادداشت، برچسب دیرکرد • آزمون آنلاین یک‌سؤال‌در‌هر‌مرحله با تایمر، تصحیح فوری و کارنامه • نتایج آنلاین/حضوری/جامع با درصد و رتبه • پومودورو با صدا، حالت تست سریع، برنامه هفتگی معلم، درصد هدف روزانه و یادآوری • مسیر یادگیری هوشمند • بازی «ذهن سریع» و داستان تعاملی «راز رصدخانه» • پروفایل با ریز امتیازهای مثبت/منفی، تقویم هفتگی، دانلود ویدیو و جزوه • پرداخت کارت‌به‌کارت با کپی شماره کارت و بارگذاری رسید • فروشگاه.

**معلم:** حضور و غیاب با یک لمس + «همه حاضر» + شمارش پیامک غیبت • ساخت تکلیف (پایه، کلاس، مهلت، امتیاز تشویقی) • گزارش تکالیف با فیلتر پایه/کلاس • ساخت آزمون آنلاین یا کاغذی با کلید پاسخ • **اسکن پاسخ‌برگ با دوربین گوشی و نمره‌دهی خودکار** • عملکرد دانش‌آموزان با امتیاز و رتبه • ویرایش مسیر یادگیری پیشنهادی • یادداشت مشاوره‌ای • امتیاز کلاسی • برنامه پومودوروی هفتگی و بررسی آن • بارگذاری ویدیو و جزوه.

**مدیر کانون:** داشبورد شاخص‌ها، نمودار پرداخت هر پایه، غایبان امروز با وضعیت پیامک • ثبت‌نام/ویرایش/حذف دانش‌آموز با جستجوی زنده و فیلتر پایه/کلاس/مدرسه • معلمان، کلاس‌ها و برنامه هفتگی • **مدیریت کلاس‌ها** (افزودن، تغییر نام، حذف یا ادغام با انتقال دانش‌آموزان، فهرست دانش‌آموزان هر کلاس، تقسیم خودکار، و «راه‌اندازی پسر/دختر» با پیش‌نمایش) [راهنما](docs/class-management.md) • مبلغ و تاریخ قفل هر پایه، صف تأیید/رد رسید با دلایل آماده، گزارش وضعیت هر کلاس • اطلاعیه به کل کانون/پایه/کلاس‌های مشخص با گزارش دیده‌شدن • حسابداری: درآمد، هزینه، مانده صندوق، نمودار مقایسه، ثبت سند، دفتر کل و دفتر واریزها با فیلتر روزانه/هفتگی/ماهانه/دلخواه • آزمون جامع با رتبه‌بندی لحظه‌ای و کارت ورود به جلسه با QR آماده چاپ • مدیریت فروشگاه و کد تخفیف • تنظیمات کانون (نام، لوگو، شماره کارت، حداقل مطالعه).

**والدین:** انتخاب فرزند • سوابق غیبت • کارنامه دیجیتال ماهانه با نمرات و معدل کل • نمودار روند پیشرفت • یادداشت دبیر راهنما • وضعیت تکالیف و اطلاعیه‌ها • پیام به معلم • فروشگاه.

**فروشگاه:** صفحه عمومی هر کانون (`#/c/ashtiani`) و صفحه جداگانه هر محصول • نشان تخفیف • سبد خرید تعاملی • کد تخفیف (`ROSHD10`، `NOKHBE20`) • پرداخت و صدور کد پیگیری.

**مدیر سامانه:** ساخت و ویرایش کانون‌ها • جستجوی همه کاربران، بازنشانی رمز، غیرفعال‌سازی • «ورود به پنل» هر کاربر برای پشتیبانی (با نوار هشدار و دکمه بازگشت) • پشتیبان‌گیری، دانلود و بازیابی.

### اسکن پاسخ‌برگ
پاسخ‌برگ از صفحه آزمون چاپ می‌شود (تا ۶۰ سؤال، با چهار نشانگر مشکی در گوشه‌ها). معلم در گوشی «گرفتن عکس» را می‌زند؛ پردازش تصویر کاملاً در مرورگر انجام می‌شود: آستانه‌گذاری Otsu، یافتن نشانگرها، تصحیح پرسپکتیو با هموگرافی و سنجش میزان پرشدگی هر حباب. پاسخ‌های تشخیص‌داده‌شده قبل از ثبت قابل اصلاح است. دکمه «تست با برگه نمونه» یک برگه پرشده مصنوعی می‌سازد تا بدون دوربین هم نمایش داده شود.

## ساختار

```
server/
  index.js        سرور HTTP، احراز هویت، کنترل نقش و قفل پنل، کار زمان‌بندی‌شده جریمه‌ها
  db.js           طرح پایگاه داده SQLite
  logic.js        امتیاز، سطح، رتبه، قفل، مخاطبان اطلاعیه، مسیر یادگیری، جریمه‌های خودکار
  util.js         هش رمز (scrypt)، توکن امضاشده، تاریخ شمسی/تهران، بارگذاری فایل
  routes/         API هر نقش: common, student, teacher, manager, parent, admin
  seed.js         داده نمونه (۴۹۵ دانش‌آموز، ۶ معلم، آزمون، حضور، پرداخت، حسابداری…)
public/
  index.html, css/app.css, fonts/ (وزیرمتن), vendor/qrcode.js
  js/core.js      API، تاریخ شمسی، اجزای رابط، نمودارهای SVG، چاپ
  js/app.js       پوسته، منو، مسیریابی، اطلاعیه تمام‌صفحه، تولد، قفل
  js/student.js teacher.js manager.js parent.js admin.js shop.js games.js omr.js common.js login.js
scripts/          backup.js, restore.js
```

## امنیت
- رمزها با scrypt و نمک تصادفی هش می‌شوند (هرگز متن ساده)؛ هش‌های ضعیف‌تر داده نمونه در اولین ورود به هش قوی ارتقا می‌یابند.
- جلسه با توکن HMAC در کوکی `HttpOnly`؛ با تغییر رمز همه جلسه‌های قبلی باطل می‌شوند.
- محدودیت تلاش ناموفق ورود (۸ بار در ۱۰ دقیقه).
- همه مسیرهای API بر اساس نقش کنترل می‌شوند و هر پرس‌وجو به کانون، کلاس یا فرزندِ مجاز همان کاربر محدود است (معلم فقط کلاس‌های خودش، والد فقط فرزندان خودش، پیام فقط به مخاطبان مجاز).
- فایل‌های بارگذاری‌شده با نام تصادفی، نوع مجاز و سقف حجم ذخیره و فقط برای کاربران واردشده سرو می‌شوند.

## فرض‌ها برای موارد مبهم

1. **پیامک:** پیش‌فرض شبیه‌سازی است. با تنظیم `ROSHD_SMS_PROVIDER` (کاوه‌نگار یا وب‌هوک) پیامک واقعی ارسال می‌شود و فقط پیامک‌های موفق «ارسال‌شده» می‌خورند. اتصال به کاوه‌نگار با کلید واقعی آزمایش نشده؛ وب‌هوک با سرور آزمایشی تست شده است.
2. **درگاه پرداخت فروشگاه** شبیه‌سازی شده و پس از تأیید، کد پیگیری صادر و درآمد در حسابداری ثبت می‌شود. حق عضویت طبق خواسته کارت‌به‌کارت با تأیید دستی رسید است.
3. **«مسیر یادگیری هوش مصنوعی»** یک موتور پیشنهاد قاعده‌محور سمت سرور است (تسلط هر درس از آزمون‌های ۶۰ روز اخیر، زمان مطالعه، غیبت و تکالیف دیرشده) که بدون اینترنت و هزینه API کار می‌کند؛ معلم آن را بازبینی و ویرایش می‌کند. در صورت نیاز می‌توان `generateLearningPath` در `server/logic.js` را به یک مدل زبانی وصل کرد.
4. **قواعد امتیاز:** پومودوروی ۲۵ دقیقه‌ای +۲؛ آزمون: درصد÷۱۰ (+۵ برای ۱۰۰٪)؛ تکلیف به‌موقع: امتیاز تشویقی همان تکلیف؛ گام مسیر یادگیری +۳؛ بازی روزانه +۳؛ پایان داستان +۵؛ امتیاز کلاسی معلم ±۲۰. منفی‌ها: غیبت بدون اطلاع −۵، تکلیف دیرشده −۵، اجرا نکردن برنامه هفتگی −۱۰، مطالعه کمتر از حداقل روزانه −۳ (جمعه‌ها معاف)، پرداخت نکردن حق عضویت پس از مهلت −۲۰. جریمه‌ها هر ۱۰ دقیقه به‌صورت خودکار و بدون تکرار اعمال می‌شوند؛ با تأیید رسید، جریمه حق عضویت حذف می‌شود.
5. **سطح‌ها** بر اساس امتیاز کل (۰، ۱۰۰، ۲۵۰، ۴۵۰، ۷۰۰، ۱۰۰۰، ۱۴۰۰، ۱۹۰۰) و **رتبه** بر اساس امتیاز کل در پایه همان کانون است.
6. **آزمون‌ها نمره منفی ندارند**؛ درصد = پاسخ درست ÷ کل سؤال‌ها. هر دانش‌آموز هر آزمون آنلاین را یک‌بار می‌دهد و زمان از سمت سرور کنترل می‌شود.
7. **کارنامه دوره‌ای** به‌صورت ماهانه (ماه شمسی) و از نتایج آزمون‌ها ساخته می‌شود: نمره هر درس از ۲۰ و معدل کل.
8. **حالت تست سریع پومودورو** (۱۰ ثانیه تمرکز / ۵ ثانیه استراحت) برای ارائه است و در پایگاه داده ثبت نمی‌شود تا امکان تقلب در امتیاز نباشد.
9. **قفل پنل** وقتی است که تاریخ قفل پایه گذشته و رسیدی تأیید نشده باشد؛ رسید «در انتظار» قفل را باز نمی‌کند تا مدیر تأیید کند. پایه‌ای با مبلغ صفر معاف است.
10. **مخاطبان اطلاعیه** دانش‌آموزان هدف و والدینشان هستند (و در حالت «کل کانون» معلمان هم). مدیر اطلاعیه تمام‌صفحه نمی‌بیند چون نویسنده آن است.
11. **پیام‌رسان:** دانش‌آموز ↔ معلمان کلاس و هم‌کلاسی‌ها؛ والد ↔ معلمان فرزند؛ معلم ↔ دانش‌آموزان و والدین کلاس‌های خودش و مدیر؛ مدیر ↔ معلمان. هیچ شماره تلفنی در پیام‌رسان نمایش داده نمی‌شود.
12. **دانش‌آموزان** با کد ملی معتبر (الگوریتم رقم کنترل) ثبت می‌شوند؛ حذف دانش‌آموز همه سوابقش را پاک می‌کند و حساب والدِ بدون فرزند هم حذف می‌شود.
13. **چندکانونی:** هر کاربر به یک کانون تعلق دارد و نام کاربری/کد ملی در کل سامانه یکتاست، بنابراین صفحه ورود مشترک است و انتخاب کانون فقط برند صفحه ورود را عوض می‌کند.
14. **منطقه زمانی** همه محاسبه‌های «امروز» و هفته (شنبه تا جمعه) بر اساس وقت تهران است.
15. ویدیوهای نمونه به یک فایل ویدیوی عمومی آزمایشی لینک شده‌اند و جزوه‌های نمونه PDF ساده‌اند؛ معلم می‌تواند فایل واقعی (تا ۱۰ مگابایت) یا لینک ویدیو بارگذاری کند.
16. پوسته روشن است (حالت تاریک پیاده نشده) و فونت وزیرمتن داخل پروژه قرار دارد تا بدون دسترسی به CDN خارجی کار کند.
