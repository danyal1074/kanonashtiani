# گزارش بررسی کامل سامانه و آزمون تاب‌آوری — ۱۸ آبان ۱۴۰۵

> دامنهٔ آزمایش: نمونهٔ محلیِ جدا با داده‌های ساختگی (seed) و دیتابیس‌های موقتِ جداگانه. به دیتابیس و کاربران سایت اصلی هیچ آزمون مخربی زده نشد.
> دو پرامت `01-Roshd-Full-System-Audit` و `02-Roshd-Resilience-Scenario-Testing` مبنا بودند. هرچه در این گزارش «اجرا شد» با خروجی واقعی همراه است؛ هرچه اجرا نشد صریحاً «اجرا نشد» نوشته شده است.

## ۱. معماری و وابستگی‌ها

| بخش | وضعیت |
|---|---|
| فرانت‌اند | JavaScript خالص (SPA با مسیر hash)، بدون فریم‌ورک و بدون build |
| بک‌اند | Node ≥ 22.13، بدون هیچ بستهٔ npm، HTTP داخلی خود پروژه |
| دیتابیس | SQLite (`node:sqlite`، حالت WAL)، فایل محلی روی همان سرور |
| فایل‌های بارگذاری‌شده | پوشهٔ `uploads/` روی همان سرور |
| DNS دامنه `kanonashtiani.ir` | ParsPack (`rain/continent.parspack.net`) — سرویس داخل ایران |
| سرور | VPS اوبونتو ۲۴؛ نام میزبان از نوع VPS خارجی است و **کشور دیتاسنتر تأیید نشد** (استعلام IP از این‌جا مسدود بود). باید از پنل میزبان تأیید شود |
| CDN، فونت یا کتابخانهٔ خارجی | **هیچ**. جست‌وجوی همهٔ `public/` و `server/` فقط لینک‌های توضیحی داخل `qrcode.js` را پیدا کرد. فونت (Vazirmatn) و QR روی خود سرور هستند |
| احراز هویت | داخلی (کوکی امضاشده)، بدون سرویس خارجی |
| پیامک | درگاه پیامک اختیاری؛ قطعی آن فقط ارسال پیامک را مختل می‌کند، نه کل سامانه |
| ایمیل / پرداخت آنلاین / اعلان push | **وجود ندارد** (پرداخت کارت‌به‌کارت با رسید تصویری) |
| کلاس آنلاین | فقط پیوند/برنامه؛ سرویس ویدیوی داخلی ندارد |
| هوش مصنوعی / آواتار | تصاویر از پیش تولیدشده و روی سرور؛ API خارجی در زمان اجرا نیست |

نتیجه: اگر اینترنت بین‌الملل قطع شود و کاربر ایرانی بتواند به **خود سرور** برسد، همهٔ صفحات و فونت و تصاویر و داده کار می‌کنند. تنها ریسک واقعی مسیر شبکه تا سرور است، نه وابستگی نرم‌افزاری.

## ۲. آنچه اجرا شد و نتیجه

| آزمون | نتیجه |
|---|---|
| آزمون دودی خودکار (`scripts/smoke.mjs`) | ۱۸۴ بررسی، همه موفق |
| دسترسی و امنیت (`scn-sec`): ۴۴ سناریو | ۴۴ موفق پس از اصلاح‌های زیر |
| خزش همهٔ پنل‌ها (۱۴۳ بازدید از دانش‌آموز، دبستان، معلم، مدیر، مدیر سامانه؛ عرض ۳۲۰/۳۹۰/۸۴۴ و بخشی از عرض‌های بزرگ‌تر؛ اجرا هنگام راه‌اندازی دوباره سرور قطع شد و کامل نشد) | بدون خطای JavaScript و بدون خطای کنسول؛ یافته‌ها در بخش ۳ |
| کشتن ناگهانی سرور (SIGKILL) حین نوشتن | ۱۰۷ نوشتن تأییدشده → ۱۰۷ ردیف پس از بازگشت؛ `integrity_check` سالم؛ بازگشت سرویس ۰٫۳۵ ثانیه |
| بازیابی پشتیبان | پشتیبان‌گیری ۰٫۲ ثانیه؛ بازیابی ۰٫۲ ثانیه؛ ۴۹۵ دانش‌آموز، `integrity_check` سالم |
| ظرفیت (آزمون‌های جلسات قبل، ۳ هستهٔ پین‌شده) | ۳۰۰ ورود هم‌زمان بدون خطا، p95 حدود ۴٫۶ تا ۵ ثانیه (محدودیت: هش رمز)؛ ۳۰۰ اولین‌ورود ۱۰ ثانیه؛ مصرف حافظه حدود ۱۲۰ مگابایت |

### اجرا نشد (صادقانه)
- آزمون اینترنت ضعیف (2G/3G، Packet Loss، تأخیر ۲ ثانیه) با ابزار واقعی شبکه.
- قطع و وصل شبکهٔ مرورگر هنگام آزمون زنده، و آزمون در گوشی واقعی.
- پر شدن دیسک، قطع اتصال دیتابیس (SQLite فایل محلی است و «اتصال» ندارد).
- بار ۵۰۰ و ۱۰۰۰ کاربر همزمان (فقط تا ۳۰۰ آزموده شد).
- نفوذ CSRF/XSS عمیق؛ فقط ورودی HTML در اطلاعیه و تزریق SQL در جست‌وجو آزموده شد.
- Playwright (در این محیط نیست؛ از ابزار CDP خودِ پروژه استفاده شد).

## ۴. یافته‌های باقی‌مانده (اصلاح نشده)

- **Low** — صفحهٔ مدیر، بخش حق عضویت: تصاویر رسید ساختگی (`/uploads/seed-receipt-N.svg`) خطای ۴۰۰ می‌دهند. فقط در دادهٔ نمونه؛ سایت اصلی رسید ساختگی ندارد.
- **Low** — صفحات «هوش‌استودیو» (`/api/exam-books/hoosh_N/pages/N`): تصویر صفحات کتاب ۴۰۴ می‌دهند؛ کار نیمه‌تمام عاملِ دیگر (طبق `docs/hoosh-book-images.md`)، نه باگ تازه.
- **Low** — چند فیلد معلم (طرح هفتگی و یادداشت دانش‌آموز) برچسب دسترس‌پذیری (`aria-label`) ندارند؛ کنتراست دو متن کوچک ۴٫۰۲ و ۴٫۲۹ (کمی زیر ۴٫۵).
- **Medium (پیشنهادی)** — اعتبار کوکی ۱۴ روز است؛ پیش از انتشار عمومی بهتر است کوتاه‌تر یا لغزان شود.

## ۵. امکان‌های آفلاین

- **کار می‌کند:** بارگذاری فایل‌های ایستا (CSS/JS/فونت/تصویر) تا حدی از کش سرویس‌ورکر؛ نصب PWA؛ نوار هشدار قطع اینترنت.
- **کار نمی‌کند:** باز شدن صفحات و داده‌ها بدون اینترنت (HTML و API عمداً کش نمی‌شوند)، ثبت پاسخ آزمون و تکلیف و پومودورو هنگام قطع (صف ذخیرهٔ آفلاین وجود ندارد). این **قابلیت پیاده‌سازی‌نشده** است، نه باگ.
- **پیشنهاد:** صف آفلاین با شناسهٔ یکتا برای هر عملیات (idempotency key) برای آزمون/تکلیف/پومودورو؛ هزینهٔ توسعه چند روز و نیازمند طراحی تعارض داده است.

## ۷. اولویت پیش از انتشار عمومی

1. تأیید کشور دیتاسنتر و تصمیم دربارهٔ انتقال یا نسخهٔ آینه داخلی.
2. پشتیبان‌گیری روزانه به مقصدی جز دیسک همین سرور.
3. صف آفلاین برای ثبت پاسخ آزمون و تکلیف.
4. مانیتورینگ و هشدار قطعی.
5. کوتاه‌کردن عمر نشست و آزمون بار ۵۰۰ نفر روی سرور تست جدا.
